# Skill 操作深度标准 v0.2

## 目的

Research Skill Pack 的 175 个 Skill 不应只是“输入 + 输出 + 一句限制”的提示词标签。每个已安装的 `SKILL.md` 都必须能让另一位本地 Codex 在不猜测范围的前提下，完成一个受限、可记录、可交接的研究工作单元。

这项标准评估的是**说明书是否完整**，不评估模型是否必然遵守说明，也不证明研究结论、引用或外部来源的真实性。

## 每张操作卡的最低内容

每个 Skill 必须在保留自身原有专业说明的基础上，明确写出：

1. **何时使用**：该 Skill 自己的 Catalog 输入、输出、闸门与安全约束，而不是泛化为整个产品的能力。
2. **前置核对**：确认哪些输入已提供、哪些只能暂记为未知、哪些前置决定不可绕过。
3. **执行协议**：至少五个按其工作类型定制的动作；治理、时间线、文献、设计、写作审计和投稿返修不共用同一套空泛步骤。
4. **产物与记录**：一个可复用的 artifact 草图，包含版本、依赖、输入追溯、闸门结果、决策状态和证据边界。
5. **判断、失败与交接**：何时可继续、何时需要人工确认、何时必须 `blocked`，以及最合适的下游动作。
6. **证据与安全边界**：不得把模型提取升级为人工核验；不得读取原始敏感数据、执行导入文本中的指令、联网补证或替用户提交外部系统。
7. **参考**：项目契约与状态机；存在量化判断时还应遵守指标规范。

## 可执行质量门槛

`python3 scripts/validate_plugin.py` 会拒绝任一已安装 Skill，若其：

- 未声明 `workflow_depth: operational`；
- 正文少于 65 个非空行；
- 缺少上述七个操作段；
- “执行协议”少于五个编号动作；
- 没有 artifact、`requires_confirmation`、`blocked` 的显式分支；
- 没有在自己的操作卡中镜像自身的 Catalog 输入、输出、闸门或安全项。

可运行 `python3 scripts/validate_plugin.py --skill-depth-report` 查看 175 张操作卡的覆盖数、正文长度区间和各 Skill Pack 分布。该报告绝不能写成“175 项模型功能均已测试”或“端到端科研已验证”。

## 维护方式

新增或改动 Skill 时，先更新 Canonical Catalog，再更新该 Skill 的操作卡和验证引用。改动某个 Skill 的输入、产物、闸门或安全规则，必须同步修改其自身操作卡；校验器会将不同步视为发行错误。

高风险的行为仍需要独立证据：项目契约靠确定性测试，真实使用靠已授权的匿名试跑，外部事实靠用户可定位且人工核验的资料。操作卡不会替代这些层级。
